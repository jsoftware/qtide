# Enhanced JQt: Windows x64 Slim build and tests

The accepted source revision is `22a0499b4165a5f0c00f3a5a65fc1ddb1b0d2761`.
The harness and build helper are maintained separately from the three implementation commits.
See [the contribution review](contribution-review.md), [table API](wd-table-extensions.md),

## Prerequisites

- Windows x64 with an interactive desktop for GUI tests.
- Visual Studio 2022 Desktop development with C++, x64 MSVC 14.44 and Windows SDK.
- Qt **6.10.3 msvc2022_64**, including Qt Core5Compat, SVG and WebSockets development modules.
  Widgets, PrintSupport, OpenGL and OpenGLWidgets are also required. Qt private headers are used;
  keep the development SDK and deployed Qt libraries at the same version.
- Python 3.10 or later; the verification environment uses Python 3.14 and only its standard library.
- A complete, matching x64 J runtime: `bin` (including `j.dll`, `profile.ijs`, Qt DLLs/plugins),
  `system` and `addons`. Verified baseline: J engine 9.7.1 and library 9.7.17.
  This repository builds JQt, not the J engine or J library.
- A separate stock JQt 2.6.6 Slim / Qt 6.10.3 runtime for the capability-fallback comparison.
- The Microsoft Visual C++ 2015-2022 x64 Redistributable must be installed, or appropriate
  licensed app-local runtime files supplied. Building does not grant redistribution rights.

Obtain J, Qt and MSVC from their respective official distributors and retain their notices.
No application runtime, owner data, Qt SDK or proprietary compiler is included here.

## Build

Use a fresh checkout and an x64 Native Tools command prompt. Replace the example paths with
explicit paths to your own SDK and checkout. Do not use the general release/ZIP script for this task.

```bat
cd /d C:\work\qtide
script\build-windows-slim.cmd C:\SDK\Qt\6.10.3\msvc2022_64
```

From a normal command prompt, provide `vcvars64.bat` as the second quoted argument:

```bat
script\build-windows-slim.cmd C:\SDK\Qt\6.10.3\msvc2022_64 "C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat"
```

The helper sets `JQTSLIM=1`, clears fat/WebKit overrides, then runs `qmake lib.pro` / `nmake`
in `lib`, followed by `qmake main.pro` / `nmake` in `main`. Nonzero tool results fail the build.
The launcher generated in `bin/win-x86_64/bin/jqt.exe` is copied beside the library in
`bin/win-x86_64/release/`. The deliverables are `jqt.exe` and `jqt.dll` there.
Slim excludes the optional multimedia/QML/WebEngine/WebKit features; it retains the required
Core5Compat, widgets, network/WebSockets, SVG, printing and OpenGL components.
Do not reuse makefiles or object files generated by another SDK/configuration.
The existing Windows qmake library post-link step may print a nonfatal self-copy diagnostic
when source and destination already coincide. The DLL is linked at its target path before
that step; retain the diagnostic in the build log and verify both outputs and their tests.

## Stage an isolated test runtime

Make a disposable copy of the complete matching J runtime into, for example,
`C:\work\jqt-test-runtime\j`. Copy the newly built **pair** into that copy's `bin`, replacing
its `jqt.exe` and `jqt.dll`. Do not overwrite an installed runtime or an accepted distribution.
Keep the matching Qt DLLs and plugins, including `platforms/qwindows.dll`.
If preparing dependencies from the SDK, use its matching `windeployqt` for the new executable
and library, then verify dependency closure; this does not supply the J engine/library or
resolve redistribution licenses. Test staging is not a distribution recipe.

Keep the stock comparison runtime in a different directory. Create a writable ASCII temporary
root, for example `C:\work\jqt-test-temp`. Run from this checkout:

```bat
python -B tests\wd\run_tests.py --jqt-bin C:\work\jqt-test-runtime\j\bin --stock-bin C:\work\stock-j\bin --temp-root C:\work\jqt-test-temp
```

All runtime paths are explicit. The runner rejects incomplete inputs and unexpected skips.
The profile driver copies recognized J profile/boot files into private sessions, redirects the
J user home, and disables user startup/profile overrides. Unknown profile layouts fail closed.
It writes no runtime files, uses no clipboard, and posts input only to the process it launched;
it does not move the real cursor. Do not run concurrently against a shared GUI desktop when
other programs may interfere with window focus or session shutdown.

## Coverage and limitations

The 27 synthetic component cases cover capability discovery and stock fallback; independent
tables; sizing/minima/widths; real header resize and click events; sort policies/indicators;
strict invalid-input handling for the new commands; cell/bulk tooltips and Unicode; hover events and deduplication;
client-side row replacement; repeated updates; and corrected child coordinates with a layout margin.
Seven harness regressions verify startup isolation, rejection of unknown/duplicate hooks,
J-error/dead-child rejection, abnormal shutdown and rejection of infrastructure errors as negative-test success. No client application imports or fixtures are needed.

Expected total: **34 tests, 33 passes, one explicit manual tooltip-popup skip**.
Tooltip strings/readback are automated; actual popup rendering requires a real pointer and
must be checked manually. On an interactive Windows desktop, hover a populated cell and
confirm its Unicode tooltip is readable and belongs to that cell. Automated tests do not
establish accessibility, every DPI/theme, or Linux/macOS behavior. These require separate review. Existing Unix installer smoke scripts and the WebAssembly J-engine
test-import helper are not Windows component regressions and are not executed in this lane.

A passing run exits zero; errors, failed assertions, abnormal shutdown and unexpected skips fail.
Keep the full build/test logs as review evidence outside the source checkout.
Historical executable fingerprints identify the exact pair used for DiskCatalogue r9; MSVC
paths/timestamps and tool revisions can change rebuilt binary hashes. Reproduction here means
building the same source/configuration and passing the regressions, not bit-identical binaries.
